# انباشتِ حضور — Accumulation of Presence

اثر Generative Art هفت‌روزه. دوربین مسیر حرکت آدم‌ها را می‌گیرد (بدون ذخیره هیچ تصویری)،
هر نفر یک «رشته حضور» می‌سازد، رشته‌ها به هم وصل می‌شوند، خوشه می‌شوند، ارگانیسم می‌شوند و
در روز هفتم یک «ابرارگانیسم» متولد می‌شود. همان جهان، زنده، روی سایت هم دیده می‌شود.

```
دوربین ──► Python (ردیابی + جهان + SQLite) ──► تلویزیون نمایشگاه (Three.js)
                         │
                         └── هر ۴ ثانیه فقط «وضعیت جهان» ──► سایت شما /presence  (Three.js)
```

---

## ۱. نصب روی ویندوز (کامپیوتر نمایشگاه)

1. **Python 3.11 یا 3.12** را از python.org نصب کنید و تیک **Add python.exe to PATH** را بزنید.
2. این پوشه را کپی کنید (مثلاً `C:\presence`).
3. روی **`install.bat`** دابل‌کلیک کنید (یک بار، اینترنت لازم است).
4. روی **`start.bat`** دابل‌کلیک کنید. مرورگر Edge تمام‌صفحه باز می‌شود و اثر شروع می‌شود.
5. برای اینکه بعد از هر ریستارت ویندوز خودکار اجرا شود: **`autostart_on.bat`**
   (این فایل Sleep و خاموش شدن صفحه را هم غیرفعال می‌کند).

| فایل | کار |
|---|---|
| `start.bat` | اجرای اثر با دوربین (اگر برنامه کرش کند خودش دوباره اجرا می‌شود) |
| `start_simulation.bat` | اجرا بدون دوربین با بازدیدکننده‌های مصنوعی (برای تست) |
| `preview_day7.bat` | پیش‌نمایش روز هفتم با ۳۰۰۰ بازدیدکننده مصنوعی (در پوشه جدا، به داده اصلی دست نمی‌زند) → `http://127.0.0.1:8077` |
| `autostart_on.bat` / `autostart_off.bat` | اجرای خودکار بعد از روشن شدن ویندوز |

خروج از حالت تمام‌صفحه Edge: `Alt+F4`

### داده‌ها بعد از ریستارت از بین نمی‌روند
همه چیز در **`data\presence.db`** (SQLite) ذخیره می‌شود؛ هر رشته حضور همان لحظه روی دیسک نوشته
می‌شود. خاموشی، کرش یا ریستارت ویندوز چیزی را پاک نمی‌کند. هر ساعت یک نسخه پشتیبان هم در
`data\backups\` ساخته می‌شود (۴۸ نسخه آخر نگه داشته می‌شوند).
برای شروع واقعی نمایشگاه، اگر قبلاً تست کرده‌اید، پوشه `data` را پاک کنید.

## ظاهر اثر: درختِ نور
همه صفحه‌ها (تلویزیون عمودی یا افقی، و سایت) یک درخت درخشان را نشان می‌دهند که از حضور آدم‌ها ساخته می‌شود:

* **رودخانه‌های نور** پایین تصویر: مسیر حرکت هر بازدیدکننده، با نورهای روان.
* **تنه** از رشته‌های نور ساخته شده؛ هر چه آدم بیشتر، رشته‌ها بیشتر. ورود هر نفر یک موج نور از ریشه تا تاج بالا می‌برد.
* **رشد در ۷ روز**: روز ۱ فقط جوانه و رودخانه، روزهای بعد شاخه‌ها، از روز ۳–۴ شکوفه‌ها، و در روز ۷ درخت کامل با تاج پر از شکوفه.
* **شکوفه‌های چشمک‌زن** (صورتی، طلایی، بنفش، آبی)، **ریزش گلبرگ‌های نورانی** از تاج و **جرقه‌هایی** که از رودخانه بالا می‌روند. نور Bloom روی همه چیز.
* **تعامل زنده**: کنار هر نفر جلوی دوربین ذره‌های گل‌مانند می‌چرخند و شاخه‌ها به حرکتش واکنش نشان می‌دهند.

## شناختن دوباره هر بازدیدکننده
اگر کسی دوباره بیاید، سیستم او را می‌شناسد و **همان بخش‌هایی که از حضور قبلی او ساخته شده‌اند** (رشته‌های تنه، شکوفه‌ها و مسیرهای قبلی‌اش در رودخانه) طلایی و درخشان می‌شوند.

* از هر چهره فقط **۱۲۸ عدد بی‌نام** (امضای چهره) نگه داشته می‌شود؛ **هیچ عکس یا ویدیویی ذخیره نمی‌شود**.
* این اعداد فقط روی کامپیوتر نمایشگاه (`data/presence.db`) می‌مانند و **هرگز به سایت فرستاده نمی‌شوند**.
* پیشنهاد می‌شود کنار اثر یک تابلو بگذارید که اثر چهره‌ها را به‌صورت بی‌نام به خاطر می‌سپارد.
* پاک کردن همه امضاهای چهره: `POST http://127.0.0.1:8000/api/admin/forget-faces` (ردهای هنری باقی می‌مانند).
* خاموش کردن: `"identity": {"enabled": false}`.

## آسیب: فریاد، ضربه، نارضایتی
سه رفتار می‌توانند **بخش کوچکی از درخت را بشکنند**:

| رفتار | چطور تشخیص داده می‌شود |
|---|---|
| فریاد یا «آه» بلند | میکروفون: صدای ناگهانی که حداقل ۲۰ دسی‌بل بلندتر از صدای پس‌زمینه سالن باشد (`shout_db`) |
| ضربه یا هجوم به سمت اثر | دوربین: بدن ناگهان به سمت صفحه بزرگ شود یا دست سریع باز شود |
| چهره ناراضی یا عصبانی | دوربین: حالت چهره (خشم، انزجار، تحقیر) چند ثانیه ادامه داشته باشد |

شاخه‌ای نزدیک به جای آن فرد می‌شکند. **تکه‌های شکسته روی کف اثر می‌ریزند و همان‌جا می‌مانند**: به رنگ اخگر نارنجی و خاکستری، و با سوسوی آرام، تا معلوم باشد آسیب دیده‌اند. لبه زخم چند لحظه اخگر می‌زند و بعد در جای خالی یک **نظم تازه** رشد می‌کند: خطوط تیز و کریستالی فیروزه‌ای و سرخ، که با بقیه درخت فرق دارد.
آسیب‌ها دائمی‌اند، در Snapshot روزها و تصویر نهایی هم می‌مانند، و روی سایت هم دیده می‌شوند.
برای اینکه اثر نابود نشود، بین دو آسیب حداقل ۱۲ ثانیه فاصله است و در هر ساعت حداکثر ۳۰ آسیب ثبت می‌شود (`cooldown` و `max_per_hour`).
تست دستی: `POST /api/damage` با `{"x": 0.3, "strength": 0.8}`

## ۲. تنظیمات — `config.json`

(بعد از اولین اجرا ساخته می‌شود. کامنت‌های `//` زیر فقط توضیح هستند، در فایل واقعی ننویسید.)

```json
{
  "start_date": "2026-10-03",        // روز اول نمایشگاه (خالی = روز اولین اجرا)
  "end_time": "2026-10-09 21:00",    // لحظه Freeze نهایی (خالی = هرگز)
  "day_override": 0,                 // برای تست: 1 تا 7
  "api_key": "یک رمز طولانی و تصادفی",
  "camera": { "index": 0, "min_area": 0.012, "debug_window": false },
  "identity": { "enabled": true, "threshold": 0.42 },
  "damage": { "enabled": true, "shout": true, "shout_db": 20, "strike": true, "displeasure": true,
              "cooldown": 12, "max_per_hour": 30 },
  "remote": { "enabled": true, "api": "https://your-site.com/presence/api.php", "interval": 4 }
}
```

* `camera.index`: اگر چند دوربین دارید 0، 1، 2 … را امتحان کنید.
* `camera.debug_window: true` یک پنجره نشان می‌دهد که دوربین چه کسانی را تشخیص می‌دهد (برای تنظیم).
* `min_area`: اگر سایه/نور اشتباه تشخیص داده می‌شود بزرگ‌ترش کنید (مثلاً 0.02).
* دوربین بهتر است بالای تلویزیون، رو به فضای جلوی آن باشد و نور محیط ثابت باشد.

### پایان روز هفتم (Freeze)
در زمان `end_time` ورودی قطع می‌شود، حرکت‌ها طی ۳ دقیقه آرام می‌شوند و اثر برای همیشه ثابت
می‌ماند (`Final State`). وضعیت نهایی ذخیره و به سایت هم ارسال می‌شود. با ریستارت هم دوباره زنده نمی‌شود.
Freeze دستی: `POST http://127.0.0.1:8000/api/admin/freeze`

### خروجی چاپ
در صفحه اثر کلید **`P`** یک PNG با ۴ برابر رزولوشن صفحه، و **`Shift+P`** با ۸ برابر (تا جایی که کارت
گرافیک اجازه بدهد) دانلود می‌کند — برای چاپ روی بوم.
کلیدهای دیگر: `H` مخفی کردن متن‌ها، `F` تمام‌صفحه، `L` برگشت به LIVE.
آدرس بدون هیچ متنی: `http://127.0.0.1:8000/presence/?clean`

## ۳. سایت — نمایش زنده در `/presence`

دو راه دارید؛ هر دو همان ظاهر و همان Timeline (DAY 1 … DAY 7 / LIVE) را دارند.

### راه A — هاست معمولی PHP (cPanel / DirectAdmin) — ساده‌ترین
1. محتویات پوشه **`web/`** را در `public_html/presence/` آپلود کنید.
2. فایل‌های پوشه **`site_php/`** (`api.php` و `config.js`) را هم در همان پوشه آپلود کنید
   (`config.js` جایگزین قبلی می‌شود).
3. در `api.php` مقدار `$API_KEY` را همان `api_key` در `config.json` بگذارید.
4. در کامپیوتر نمایشگاه، در `config.json`:
   `"remote": {"enabled": true, "api": "https://your-site.com/presence/api.php"}`
5. سایت: `https://your-site.com/presence/`

### راه B — سرور/VPS با Python
روی سرور همین پروژه را بگذارید و اجرا کنید: `python run.py --mirror`
(در `config.json` سرور همان `api_key` را بگذارید). پشت Nginx با WebSocket روی `/ws` تنظیم کنید.
در کامپیوتر نمایشگاه: `"remote": {"enabled": true, "api": "https://your-site.com/api"}`

اگر اینترنت نمایشگاه قطع شود، اثر در نمایشگاه بدون مشکل ادامه می‌دهد و به‌محض وصل شدن، سایت
به‌روز می‌شود. روزهای گذشته (Snapshot هر روز) هم به سایت ارسال می‌شوند.

## ۴. API

| متد | آدرس | توضیح |
|---|---|---|
| GET | `/api/state?since=v` | وضعیت کامل جهان (اگر تغییری نکرده: `{"same":true}`) |
| GET | `/api/stats` | Visitors, Connections, Memories, Day, Evolution |
| GET | `/api/snapshots` | روزهای آرشیو شده |
| GET | `/api/snapshot/{1..7\|final}` | جهان یک روز خاص |
| GET | `/api/live` | بدن‌های زنده جلوی دوربین |
| WS  | `/ws` | بدن‌های زنده (۱۵ بار در ثانیه) + اعلام تغییر نسخه |
| POST | `/api/ingest` | (سایت) دریافت داده از نمایشگاه — هدر `X-Api-Key` |
| POST | `/api/presence` | افزودن حضور از سنسور دیگر: `{"points":[[x,y],...],"duration":3}` |
| POST | `/api/damage` | شکستن بخشی از اثر: `{"x":0.3,"strength":0.8,"cause":"strike"}` |
| POST | `/api/admin/forget-faces` | پاک کردن همه امضاهای چهره |
| POST | `/api/admin/freeze` | Freeze نهایی |
| GET | `/api/export` | آرشیو خام همه رشته‌ها (JSON Lines) |

مستندات تعاملی: `http://127.0.0.1:8000/api/docs` — روی هاست PHP همان مسیرها به شکل
`api.php/state`، `api.php/snapshot/3` و … هستند.

## ۵. منطق اثر (خلاصه فنی)

* **رشته حضور**: مسیر هر نفر (بعد از خروج از کادر) → یک خط ظریف با ~۲۰٪ شفافیت.
* **انباشت غیرخطی**: `growth = (log10(1+visitors)/4)^2.2` — تا ۲۰ نفر تقریباً خالی، ۱۰۰۰۰ نفر اوج.
* **خلق → اتصال → ادغام → فشرده‌سازی → تکامل**: هر رشته به نزدیک‌ترین خوشه جذب می‌شود؛ هر ۲۰ ثانیه
  خوشه‌های نزدیک ادغام و گره‌هایشان فشرده می‌شوند، طوری که هزاران رشته به ~۲۰ ساختار بزرگ تبدیل شوند
  (پیچیدگی بیشتر، نه شلوغی).
* **هفت روز**: Birth، Memory (رانش آهسته)، Connection، Organism (حجم و تنفس)، Collective (ورود
  هم‌زمان چند نفر = موج در کل شبکه)، Complexity، Emergence (اتصال همه حافظه‌ها به یک ابرارگانیسم).
* **تعامل زنده**: دست بالا → کشش به بالا، دست‌های باز → شبکه فاصله می‌گیرد، حرکت سریع → موج،
  بی‌حرکتی → آرامش، دو نفر نزدیک هم → اتصال بین آن‌ها. با رفتن فرد فقط یک رشته کوچک در حافظه می‌ماند.
* تصویر یا ویدیو ذخیره نمی‌شود؛ فقط مختصات مسیر حرکت (و در صورت فعال بودن، امضای عددی بی‌نام چهره).
* مدل‌های چهره (حدود ۷۵ مگابایت) هنگام `install.bat` یک بار دانلود می‌شوند و در پوشه `models` قرار می‌گیرند.
* اگر میکروفون یا مدل‌ها در دسترس نباشند، اثر بدون آن بخش‌ها کار می‌کند.
